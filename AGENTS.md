# AGENTS.md — Sketched courses

Guide for coding agents working in this repo. Read it fully before changing anything.

## What this is

A monorepo of **interactive course sites** that share one engine and one UI. Each lesson is a short story told with an **animated isometric SVG diagram**: a problem appears, a technique fixes it, the numbers react, and the learner can break things on purpose.

| App                  | Site name         | Topic                        | Break-it actions                                                           |
| -------------------- | ----------------- | ---------------------------- | -------------------------------------------------------------------------- |
| `apps/system-design` | Systems, Sketched | System design for engineers  | kill a server, spike traffic, slow the database                            |
| `apps/finance`       | Money, Mapped     | Personal financial education | surprise bill, lose your income, rates rise, market crash, new money stops |

- Static sites, **no backend** in v1. A Spring Boot API (accounts, synced progress) comes later. Do not add one.
- Each site's name and author live only in its `src/config.ts` (`SITE_NAME`, `AUTHOR_NAME`).
- The finance site is **education only**. Its lessons give general concepts with simplified example numbers, never personal advice, product recommendations or real tickers. The disclaimer (`notice` in its config) must stay on every lesson.

### Originality rule (non-negotiable)

Never copy text, lesson content, illustrations, colours, CSS or code from any existing site (including designed-to-scale.vercel.app). All lesson wording, diagrams and visual tokens must be original. Scheme and company names in lessons must be fictional.

## Commands

Run from the repo root. Node 22+, pnpm 12.

| Command                             | Use                                                               |
| ----------------------------------- | ----------------------------------------------------------------- |
| `pnpm install`                      | Install everything                                                |
| `pnpm dev` / `pnpm dev:finance`     | Dev server: system design at :5173, finance at :5174              |
| `pnpm build`                        | Production build of every app → `apps/<app>/dist`                 |
| `pnpm test`                         | Vitest in every package                                           |
| `pnpm lint`                         | ESLint (flat config, typescript-eslint strict, react-hooks)       |
| `pnpm typecheck`                    | `tsc` in every package and app                                    |
| `pnpm knip`                         | Unused files, dependencies and exports                            |
| `pnpm format` / `pnpm format:check` | Prettier                                                          |
| `pnpm validate`                     | Check every app's lessons and that each `catalog.json` is current |
| `pnpm lessons`                      | Validate **and regenerate** every `catalog.json`                  |
| `pnpm e2e`                          | Playwright smoke tests for every app (desktop + mobile)           |

Single package: `pnpm --filter @ss/diagram-engine test`. Names: `@ss/theme`, `@ss/ui`, `@ss/lesson-engine`, `@ss/diagram-engine`, `@ss/course`, `@ss/system-design`, `@ss/finance`, `@ss/tools`.

## Definition of done

A change is done only when all of these pass. CI (`.github/workflows/ci.yml`) runs the same list, then `pnpm e2e`.

```bash
pnpm format:check && pnpm lint && pnpm knip && pnpm validate && pnpm typecheck && pnpm test && pnpm build
```

If you touched UI, routing, keyboard handling, the engine or a preset, also run `pnpm e2e`. Shared code affects **both** sites, so check both. Never claim something works without running these. Report failures with the real output.

## Architecture rules

1. **`diagram-engine` must never import React** or anything from `ui`, `course` or apps. It exposes an imperative API:
   `createStage<M, A>(svg, { initial, changes }, { reducedMotion, scheduler, scenarios, summarize, formatValue })` → `goToStep`, `play`, `pause`, `replay`, `break`, `reset`, `onMetrics`, `current`, `setReducedMotion`, `destroy`.
2. The engine core is **domain-neutral**. Metrics (`M`) and break actions (`A`) are type parameters. Everything domain-specific lives in a **preset** (`src/presets/*.ts`): a metrics interface, an action union, a `Scenarios<M, A>` map, `ACTION_NEEDS`, and a `summarize` function.
3. `packages/ui/src/DiagramStage.tsx` is the **only** React wrapper around the engine. `ui` components take plain props and `labels`; they hold no course-specific strings or thresholds.
4. `packages/course` is the whole site. An app only supplies a `CourseConfig<M, A>`: catalog, chapters, `loadLesson`, home text, `engine` (preset scenarios, summary, value formatter), `metricTiles` (labels, formatting and warn/fail thresholds), `actionLabels`, `legend`, an optional `notice`, and optional overrides for the shared strings. Don't copy pages into an app; extend `CourseConfig` instead.
5. Dependency direction: `theme` ← `ui` → `lesson-engine` → `diagram-engine`; `course` → all of those; apps → `course` + `diagram-engine` + `lesson-engine` + `theme`. Never the reverse.
6. **A new course is a new app plus, if needed, a new preset.** Steps:
   1. Copy `apps/finance` and change its name, port and favicon.
   2. Write the preset (and any new node kinds), with unit tests.
   3. Write `config.ts`, `chapters.ts` (re-exporting the preset's needs as `ACTION_NEEDS`) and the lessons.
   4. Add a smoke test, and a launch config entry in `.claude/launch.json`.
7. Scenarios are **deterministic**: pure functions of the step state and elapsed time. No `Math.random` and no wall-clock reads. Time comes from the injectable `Scheduler`. `phaseAt(t)` changes whenever the diagram should re-render (for example once per simulated month); `metricsAt(t)` can change every frame.
8. Each shape is a pure function `(node) → SVG markup` in `shapes.ts`, drawn around the node's floor centre. Colours come from CSS custom properties set on the wrapping group (`palette.ts`), so health changes cross-fade. To add a node kind:
   - add it to `NodeKind`, `SHAPES` and the palette token map;
   - add a `--node-<kind>` / `--node-<kind>-soft` pair to `tokens.css` in all three theme blocks.
9. Diagram rendering is SVG, not canvas/WebGL/three.js.

## Diagram engine facts

- Projection (`iso.ts`): `sx = (x − y)·cos30°·UNIT`, `sy = (x + y)·sin30°·UNIT − z·UNIT`, `UNIT = 26`. Node `x`/`y` are **floor grid cells**, not pixels.
- Visible faces: `left` = face looking down +y, `right` = face looking down +x. Left ≈ 12% darker, right ≈ 22% darker.
- Depth order: `x + y`, then `z`, then input order (`depthSort`).
- Links are orthogonal floor routes: straight if aligned, otherwise a Z-shape split at the midpoint of the longer axis. Lay nodes out so these routes don't cross blocks.
- The floor and viewBox cover every node in **every** step, so the frame never jumps.
- `goToStep(i)` applies diffs `0..i`; `-1` is the initial state. A shape is redrawn when its kind, `value` or `capacity` changes.
- **Stat pill:** if a node has `value`, the pill shows `formatValue(value)`, for example `$1,250`. Otherwise, if it has `capacity`, the pill shows its load, meaning request flows through the node ÷ capacity (`response` and `healthCheck` flows don't count). A jar's coin level is `value / capacity`. Pill tone follows health.
- Flow kinds: `request` = the main thing moving (requests, money), `response` = what comes back (responses, interest, returns), `failed` = bounces back in red, `healthCheck` = small muted pings.
- **Infra preset:**
  - `killServer` kills the second healthy server, or the only one. Its traffic fails for 3 s, then gets rerouted. With a single server, errors stay at 100%.
  - `spikeTraffic` applies 5× load; any node over 85% becomes degraded.
  - `slowDatabase` adds latency scaled by `databaseShare()`, so a good cache hides it from p95.
- **Money preset** (one simulated month per second):
  - `loseIncome` stops the employer, drains the jar by `spending` each month, and then turns the shortfall into debt shown as red flows.
  - `surpriseExpense` is a bill of 1.5 months of spending. The jar pays what it can, and the rest becomes debt borrowed from a linked bank.
  - `rateHike` adds 5 percentage points a year on `debt`.
  - `marketDrop` takes the first market node down 35%, then recovers it to +12%.
  - `newMoneyStops` cuts inflows to the scheme, drains it, and collapses it. Every person linked to the scheme loses their `value`, and net worth drops by the stake on the node with id **`you`**.
- Reduced motion: no packets and instant transitions, but scenario metrics still update.
- `requestAnimationFrame` pauses in hidden tabs, and the scenario clock pauses with it. That is intended.

## Writing or editing a lesson

1. Create `apps/<app>/src/lessons/<slug>.ts`. The file name must equal `slug` (kebab-case). Default-export a lesson typed with the app's preset, e.g. `Lesson<MoneyMetrics, MoneyAction>`.
2. Add the slug to its chapter in that app's `chapters.ts`. `lesson.chapter` must equal that chapter's `title`.
3. Run `pnpm lessons` and commit the regenerated `catalog.json` with the lesson.

Schema rules the validator enforces (`packages/lesson-engine/src/validate.ts`):

- At least one step, and a non-empty `youWillLearn`. Each item is `{ text, stepId }` and is ticked when the learner reaches that step.
- No repeated node, link or step ids.
- Each step's `change` is a **diff** from the previous step: `add`, `remove`, `update`, `flows` (replaces the active flows; omit it to keep them), `metrics` (partial merge).
- Never remove or update something that doesn't exist. **Before removing a node, remove its links in the same change**; a dangling link is an error.
- Every flow hop (`route[i] → route[i+1]`) needs a link between those nodes, in either direction.
- `body` paragraphs may contain only `<b>` and `<code>`. They are rendered by `RichText` without `dangerouslySetInnerHTML`.
- Every `breakActions` entry must exist in the app's `ACTION_NEEDS`, and the node kind it needs must be on stage at that step.

Content style:

- 7–12 steps, following problem → idea/solution → TRY IT → trade-off → recap.
- One idea per step, short sentences, concrete numbers, and a `keyIdea` on most steps. No filler, lorem ipsum or emoji.
- **Numbers must agree** across body text, `metrics`, node `value`s, flow rates and what the scenario will produce. Compute them (loan payments, compound growth, payoff months) rather than guessing. The finance lessons assume 7% a year for investing, and USD.
- `short` is one or two words. It shows under the stepper circle and on the Next button.
- After layout changes, look at the step in the browser at desktop and phone widths. Check that labels and stat pills don't overlap and links don't run through blocks.

## Code conventions

- TypeScript `strict`, plus `noUncheckedIndexedAccess` and `verbatimModuleSyntax`. Use `import type` for types.
- No `any` and no non-null assertions (`!`); lint fails on both. Narrow types or use `?? fallback` instead.
- No dead code, unused exports or placeholder components. knip enforces this; un-export anything that is only used internally.
- React 19: `ref` is a normal prop and context uses `<Context value>`. Don't call `setState` synchronously inside `useEffect` (the react-hooks rule fails); derive state instead.
- Styling: CSS Modules plus design tokens only. No UI component library, no inline colour values, no gradients, glassmorphism or emoji.
  - Radius: 8 px controls, 10 px tiles, 14 px panels.
  - Motion: 150–350 ms with `var(--ease)`.
  - Buttons have a hard bottom shadow.
- Fonts: IBM Plex Mono for headings, labels, numbers and buttons; IBM Plex Sans for body text. Import latin subsets only.
- Strings:
  - Shared UI strings live in `packages/course/src/i18n/en.json` and are read with `useCourse().t(key, vars)`.
  - Course-specific strings live in each app's `src/i18n/en.json`.
  - Lesson text is structured so a Khmer (`km`) translation can be added later; KM shows as "coming soon".

## Theme

- Tokens are in `packages/theme/src/tokens.css`. Light is the default. Dark follows the system unless `data-theme` on `<html>` overrides it, so **every token must be defined in three places**: `:root`, the `prefers-color-scheme: dark` block, and `:root[data-theme='dark']`.
- Node colours exist for all 16 kinds (8 infra, 8 money).
- The theme choice is saved in `localStorage` under `ss:theme`, and progress under `ss:progress`. Each site runs on its own origin, so the two sites don't collide.
- Contrast: text ≥ 4.5:1 and diagram graphics such as links ≥ 3:1, in both themes. Recheck if you change a colour.

## Accessibility and performance bar

- WCAG AA, full keyboard use, visible focus, an `aria-label` on every icon-only button, and support for `prefers-reduced-motion`.
- The stage SVG has `role="img"` and an `aria-label` summary from the preset's `summarize`. A debounced live region announces changes.
- Keyboard: `←`/`→` change step, `R` replays, `Space` pauses, `⌘K`/`Ctrl K` opens search. The keys are ignored while typing in a field, and Space is ignored on buttons.
- Initial JS ≤ 150 KB gzipped per app (about 104 KB now). Each lesson must stay a separate lazy chunk. Lighthouse ≥ 95 for Performance and Accessibility.

## Testing

- **Engine** (`packages/diagram-engine/src/**/*.test.ts`):
  - projection, depth sort and step diffs;
  - each preset's scenarios (`presets/*.test.ts`);
  - stage behaviour using a manual `Scheduler` with happy-dom (`// @vitest-environment happy-dom`). Drive time with the fake scheduler, never real timers.
- **Lesson engine**: validator (including action needs), outline/catalog, progress, keyboard mapping. **Course**: `search.test.ts`.
- **Playwright** (`apps/<app>/e2e/smoke.spec.ts`; system design previews on :4173, finance on :4175):
  - System design: kill a server → errors rise, then return to 0%; progress on home; ⌘K search.
  - Finance: lose your income with no savings → debt appears; a full fund absorbs a surprise bill; a scheme collapse removes your $2,000 stake.
  - Wait for the lesson heading before pressing keys, because lessons load lazily.
  - Use `exact: true` for button names, because stepper buttons contain step titles.
- Add or extend tests with every behaviour change. Engine and preset changes need unit tests.

## Gotchas

- **TypeScript is pinned to `~6.0`** because typescript-eslint doesn't support TS 7 yet. Don't upgrade it on its own.
- `catalog.json` is generated. Editing a lesson without running `pnpm lessons` fails `pnpm validate` in CI.
- `LessonPage` keeps `targetRef` so quick repeated arrow presses aren't lost (`navigate()` updates the URL before React re-renders). Keep that pattern if you touch navigation.
- Dev preview configs live in `.claude/launch.json` (system-design :5173, finance :5174).
- Hosting: each app is a static SPA with its own `vercel.json` and `public/_redirects`. Deploying is a human decision; don't deploy without being asked.

## Working agreement

- Before coding a sizeable change, list the files you'll create or edit, then build.
- If something is ambiguous, state your assumption in one line and continue. Ask first only before deleting data or changing a decision recorded in this file.
- Keep commits small and focused, one logical step each. Commit only when asked.
- When reporting, use: **Files** · **Assumptions** · **Concerns** · **Tests result** · **Next step**.
- Out of scope for v1: accounts, backend, comments, quizzes, a "Design Lab", a trading-chart engine.
